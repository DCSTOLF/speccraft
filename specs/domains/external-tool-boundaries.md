# Domain: external-tool-boundaries

Speccraft defers routing for external tools it does not own (code-intel/call-graph) to the user's environment; no brand endorsements in model-loaded, template, or human-facing surfaces.

- Speccraft defers all code-intelligence routing (call-graph / symbol-search tool choice) to whatever tool the user has installed; its skills, commands, and templates do not enumerate or express a preference for a specific tool (spec 0011)
- Templates under `templates/speccraft/` stay stack-agnostic and name no specific external enforcement tool; a code-intel tool may appear only as a neutral example ("such as CodeGraphContext"), never as a recommendation (spec 0011)
- Prescriptive routing prose toward an unowned external tool ("prefer it over grep/find", "use its tools", "the recommended way", "should install ... alongside speccraft") is disallowed in every speccraft surface including human-facing `README.md` and overview docs; neutral labels such as "Recommended companions" are retained (spec 0016)
- The `/speccraft:spec:review` payload is TIERED by a fixed table keyed on identity, never on size: the spec content plus `.speccraft/guardrails.md` and `.speccraft/index.md` are INLINE (pasted verbatim, because guardrails must be unmissable), while `.speccraft/architecture.md` and `.speccraft/conventions.md` are REFERENCE (a repo-relative path, a byte size, and a `^##`/`^###` heading index in file order). Classification resolves against `speccraft-state find-root` and matches the full repo-relative `.speccraft/<name>`, never the trailing basename, so `vendor/other/.speccraft/conventions.md` and a spec document sharing the basename are errors; any path outside both tables is an error, `.speccraft/history.md` included, since nothing is added to what a reviewer sees (spec 0052)
- Heading extraction is one fence-aware `LC_ALL=C awk` pass emitting `^## ` and `^### ` in file order: a fence opens on three or more backticks or tildes (info string allowed, indentation allowed) and closes only on the same character at the same or greater length, an unclosed fence suppresses headings to EOF, and a trailing CR is stripped so a CRLF checkout yields an identical record. It uses NO regex interval expression, because mawk does not implement them and matches nothing silently while the identical spelling works under GNU `grep -E` (spec 0052)
- `commands/spec/review.lib.sh` is the SOLE byte-producing owner for review dispatch, and `review_compose_payload` is the single composer for both the full round and the spec-0035 scoped `--diff` round — a second composer would mean a second answer to "what was sent" and the budget can only measure one. It emits the payload to STDOUT only, rejects a reference-tier file passed in the inline position, errors on a named-but-missing reference file, emits the reference section with an explicit "none" marker for an empty set, and writes exactly one other file: the `--digest-out` sidecar carrying `<sha256>  <repo-relative-path>` lines, which exists so the composition-time digests never enter the payload (spec 0052)
- Reviewer payloads are bounded BEFORE dispatch by `review_budget_check <bytes> <input-mode>`, which echoes `ok` or `refuse:<reason>` and exits 0 in both cases because a refusal is data, not a shell failure: `REVIEW_MAX_ARGV_BYTES` (65536, the field-reported ~70 KB argv working limit rounded down to a power of two, and a conservative policy floor rather than a guarantee of process creation) applies to `argv` AND `acp` since ACP is invoked as `acpx <agent> <prompt>` and is therefore argv transport; `REVIEW_MAX_PAYLOAD_BYTES` (262144, the next power of two above the largest payload ever observed to complete against both shipped CLIs) applies to every mode; `stdin`, `file`, and an absent `input` key take the payload limit only; an unrecognised mode is an error so the next argv transport cannot slip in exempt; and `refuse:payload-limit` wins deterministically when both bite. `getconf ARG_MAX` probing is rejected — it would make the refusal boundary vary by machine (spec 0052)
- An over-budget agent is refused PER AGENT, before dispatch, with a remedy specific to the limit that bit: `review_refusal_message` names the agent, its input mode, the measured bytes, the numeric limit from the RUNTIME effective value (so the diagnostic cannot disagree with the behavior when an override is in play), the inline files ranked by size, and either the literal `input = "stdin"` migration plus `.speccraft/agents.toml` for an argv-limit refusal or compaction/a shorter spec for a payload-limit one — never the migration line for the latter, since stdin does not help there. `REVIEW_MAX_ARGV_BYTES`/`REVIEW_MAX_PAYLOAD_BYTES` are accepted only as base-10 integers >= `REVIEW_MIN_LIMIT_BYTES` (1024); any other value warns on stderr naming the variable and proceeds with the compiled default rather than aborting the review (spec 0052)
- The payload is materialized EXACTLY ONCE and measured as dispatched: `review_round_tmpdir` creates a 0700 directory and installs a cleanup trap on `EXIT HUP INT TERM` immediately (it sets a variable rather than echoing a path, because a command substitution would install the trap in a subshell that exits at once; `SIGKILL` is a stated uncoverable boundary), `review_materialize_payload` redirects the composer stdout once into a single 0600 artifact and REFUSES one that already exists, and that same artifact is what gets piped to stdin, passed via `--file`, or read for argv. `review_dispatch_bytes` uses a byte-preserving read because reading into a variable would strip trailing newlines at the file-to-argv boundary. `review_payload_representable` rejects a NUL byte (POSIX argv cannot carry one) or invalid UTF-8, naming which failed. No debug or convenience copy may be written anywhere — a cached full prompt would restore the unbounded artifact by a side channel while the budget check still reported success (spec 0052)
- Reference-tier reads are ATTESTED, not assumed: the reviewer returns `reference_access: [{path, sha256}]` for every reference path and reports unreadable ones in `reference_access_failures: [{path, reason}]`, with the expected digests withheld from the payload — a digest cannot be produced without reading the bytes, whereas an in-prompt sentinel would prove only that the reviewer read the prompt. `review_validate_reference_access` is exact (every expected path present exactly once, no unknown path, every digest matching, no duplicate, an empty failures list) and tolerant of how the CLIs actually wrap YAML; a verdict failing any arm counts toward NEITHER round predicate, the same rule as a timeout, and is reported in its own category so a chronically failing reviewer is diagnosable. The guarantee is deliberately the weaker one: it proves a process with filesystem access at the dispatched cwd obtained the bytes, NOT that the model reasoned over them (spec 0052)
- Reviewer capability is a dispatch contract with two halves. Subagents declare `Read` in `agents/*.md` frontmatter. External CLIs carry a `reference_read` flag in `.speccraft/agents.toml` that is OPT-OUT — an absent key means `true`, because every already-initialized repo lacks it and requiring it would have made every configured reviewer ineligible on the first `git pull`; only an explicit `reference_read = false` refuses reference-tier dispatch, with a named message. Both halves are invoked with cwd set to the root `speccraft-state find-root` reports for the active spec (in a workspace, the member repo), since reference-tier paths are only resolvable there (spec 0052)
- `aux-delegator` is a PURE DISPATCHER for review rounds: given a precomposed payload artifact, an input mode and a cwd, it sends those bytes unmodified and must NOT re-prefix the review template, re-inline context files, or write another copy for `input = "file"` (it passes the artifact itself). Left composing, a round would compose twice and the bytes the budget measured would not be the bytes dispatched — the materialize-once rule broken by the component furthest from the check. Its `implement` and `analyze` modes are unchanged, asserted byte-identical rather than described as such. `templates/speccraft/agents.toml` ships `input = "stdin"` for every agent with an explicit `reference_read = true`; repos already initialized own their copy and are never rewritten, so the argv refusal is their migration nudge (spec 0052)
