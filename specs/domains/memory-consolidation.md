# Domain: memory-consolidation

Keeping memory bounded-and-true: confirm-gated `history.md` compaction and on-close/backfill consolidation of spec requirements into `specs/domains/<area>.md`.

- `/speccraft:history:compact` is the ONLY operation that rewrites `.speccraft/history.md`; a non-blocking `spec:close` nudge suggests it purely as a function of size — true iff `count > N` AND (`count > 15` OR `bytes > 40 KB`) — and the nudge itself edits nothing (spec 0024)
- Compaction keeps the first N (default 10) `## YYYY-MM-DD`-headed ADR entries in file order verbatim, counting on the date header alone (never the optional trailing `(spec NNNN)` suffix); everything below the window is eligible for compaction (spec 0024)
- Below-window entries are removed into a single merged `## Compacted` section of `###` theme groups (title, `Specs:`, `Archive:` pointer, one-paragraph summary, optional `Supersedes:`) and appended verbatim to append-only `.speccraft/history-archive/history.md`, deduped by full-entry byte-match; supersession collapse is heuristic, out-of-window-only, and proposed not applied (spec 0024)
- Re-compaction merges newly-demoted entries into the existing `## Compacted` section (durable input, never regenerated); compaction is confirm-gated, a no-op when nothing is below the window, touches only `history.md` + `history-archive/`, and `history-archive/` is never added to the `speccraft-context` load list (spec 0024)
- On `/speccraft:spec:close` (and retroactively via `/speccraft:sync`) a spec's final requirements are merged into open-set domain files `specs/domains/<area>.md` (a domain exists iff its file exists — no registry); consolidation is confirm-gated at every step and never blocks close, and the deterministic mechanics live in pure-shell `commands/spec/consolidate.lib.sh` (no Go binary, no override) while the prose/merge reuses `memory-keeper`'s `Mode: consolidate` (spec 0025)
- Routing is explicit-then-seeded: frontmatter `domains:` is authoritative, else the proposal is grounded on `consolidate_existing_domains` (live `specs/domains/*.md` area names, bytewise-sorted, `.archive` excluded) to prefer a fitting existing domain or else propose a clearly-named new one, always presented for confirm/correct (never silent), and a multi-domain spec is split per-domain and shown before any write (specs 0025, 0029)
- Merge vocabulary is ADD/MODIFY/REMOVE (explicit `delta:` block authoritative, else a model-inferred fallback confirmed); every MODIFY/REMOVE carries a verbatim target locator matched by exact normalized comparison with the trailing `(spec NNNN)` suffix stripped — zero/many matches fall to the conflict path, a missing locator is a malformed-block rejection — and merged lines carry a list-valued `(spec NNNN)` provenance suffix (spec 0025)
- A conflict is proposed/confirmed and never blocks close: decline leaves the domain line byte-unchanged and records the open conflict in `specs/NNNN-slug/consolidation-conflicts.md` inside the spec dir, and the helper deletes that file once all its conflicts resolve (spec 0025)
- Two clock-free archives: superseded requirement text is appended to `specs/domains/.archive/<area>.md` (self-describing header + verbatim suffix-bearing text, full-entry byte-dedup), and the closed spec dir is MOVED wholesale to `specs/.archive/NNNN-slug/` (frontmatter `status` stays `closed`; location signals "consolidated") as the LAST step only when zero conflicts remain; per-delta order is archive-B, then domain mutation, then dir-move, making crash/re-runs idempotent (spec 0025)
- `/speccraft:sync` backfill consolidates any candidate (`status==closed` AND still under `specs/` AND no `consolidation-skip` marker) replayed in `history.md` chronological order (oldest-first, reusing 0024's parser; history-less specs last by `created:` then id); each candidate is proposed once per run, a sync-decline writes a `consolidation-skip` marker for across-run skip-permanence whereas an inline-close decline writes no skip, and live `specs/domains/<area>.md` join the `speccraft-context` load list (lazy by area) while both `.archive/` trees never do (spec 0025)
- Consolidation routes ONLY to `specs/domains/<area>.md` and NEVER writes `.speccraft/architecture.md`/`conventions.md`/`history.md`; the step-4 `memory-keeper Mode: close` memory updates are a separate concern and never a substitute for step-9 `Mode: consolidate`, and a missing `delta:`/`domains:` is a confirm-gated model-proposed fallback, never a reason to skip (spec 0029)
