# Domain: workspace-conductor

Multi-repo workspace orchestration: `kind`/`workspace.yml` topology, `ledger.md` + reconcile rollup, the `/speccraft:arch:orchestrate` conductor, and crash-safe re-entry (the design-0001 conductor arc, specs 0037–0040).

- A repo declares `kind = "repo"|"workspace"` in `speccraft.toml` (absent ⇒ `repo`; unknown coerced to `repo` by non-strict `ReadConfig`, rejected by `ReadConfigStrict`); `FindWorkspaceRoot(dir)` resolves the nearest `kind = workspace` ancestor else exactly `FindRoot(dir)`, and is consumed only by `arch:*`/the conductor — the hook/guard hot path references only `FindRoot` (spec 0037)
- A `workspace.yml` at the workspace root lists members as a constrained hand-rolled `members:` / `  - path: <rel>` subset (no YAML dependency; inline `#` comments stripped; absolute paths and empty values are parse errors); the listed membership is authoritative and presence-preserving — each member carries a `Present bool`, a missing one warned not dropped — surfaced by `speccraft-state list-members` (spec 0037)
- `speccraft-state get-status <NNNN-slug>` reads a spec's `status:` with dual live→`.archive` resolution (live wins), and `get-frontmatter <spec.md> <key>` reads any frontmatter field (e.g. `design:`/`informed-by:`); both go through the single `parseFrontmatterBlock` grammar as advisory pull-only links with no referent resolution (spec 0037)
- `ledger.md` at `<workspace-root>/.speccraft/ledger.md` is a `history.md`-class markdown memory file written via `AtomicWriteFile` (deliberately outside the `state.json` single-writer rule); its grammar is `## design <id>` → `### <member-path>` → `<key>: <value>` fields over the fixed set `{spec,last_completed_phase,in_flight,blocked,updated}`, read by `ParseLedger` and upserted by `SetLedgerField` (idempotent, `updated` auto-stamped, empty value clears a field) (spec 0038)
- `Reconcile` / `speccraft-state reconcile <design-id>` rolls a design up across members keying on each member spec's real frontmatter `status` (never the ledger's `last_completed_phase`) while honoring the ledger's `blocked` overlay; classification is Blocked → Closed(`closed`/`archived`) → InProgress (mutually exclusive), and `Done` iff every member classifies Closed (spec 0038)
- `/speccraft:arch:orchestrate` (a `commands/arch/orchestrate.md` runbook + bats-tested `orchestrate.lib.sh`) drives each workspace member through the lifecycle by sequencing the existing per-spec commands cwd-scoped into the member repo (`(cd '<member>' && …)`, single-quoted, never `--root`), resuming from the ledger pointer, writing `in_flight` before a dispatch and clearing it after, and isolating a failure as a per-member `blocked` while siblings continue (spec 0039)
- The ledger token sequence is `new → reviewed → planned → implemented → validated` (the Socratic `answer-questions` folded into `spec:new`; `revise` loops within review without advancing the pointer; `validate` gates on the member's test command then closes via `spec:close`), with two human checkpoints — after `planned` (suppressed by `--straight-through`) and on review-loop escalation at `max` — and decomposition is model-drafted/human-confirmed, parsed by `orch_parse_decomposition` under a safe relative-path charset (spec 0039)
- On resume the conductor is crash-safe: before re-dispatching an `in_flight` member it inspects the member's real `spec.md` status and, via `orch_reentry`, either adopts the already-done result (jumping the ledger pointer to the artifact's true position, clearing `in_flight`/`blocked`, no re-dispatch) or reattempts — never double-allocating a spec or re-closing a `closed` one, and tolerating an out-of-band multi-phase jump (spec 0040)
- `orch_find_member_spec` recovers a crashed `new` phase by adopting the existing member spec whose frontmatter `informed-by: [design/<id>]` back-references the design (≥2 matches, or a `get-frontmatter` read failure, error rather than silently guessing); seeding is idempotent create-if-absent (never re-`spec ""`, so a captured ref is never erased), and the review loop's `in_flight` is the structured `phase=review iteration=<n>` (spec 0040)
