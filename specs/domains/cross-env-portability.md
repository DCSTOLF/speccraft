# Domain: cross-env-portability

Executing correctly outside the dev devcontainer: plugin-root self-resolution and zsh-safe sourcing of `commands/**/*.lib.sh`.

- Every `commands/**/*.lib.sh` that resolves its own directory uses the single canonical cross-shell idiom `${BASH_SOURCE[0]:-$0}` so it sources under bash and real zsh with `set -u`; an exact-form grep guard rejects any other `${BASH_SOURCE[0]}` use, and a real-`zsh -uc 'source …'` leg (zsh is a declared test prerequisite, never silently skipped) pins it (spec 0029)
- `speccraft-state plugin-root` prints and validates the plugin's own install directory; a directory is a valid root iff it contains all of `.claude-plugin/plugin.json` (the identity anchor), `bin/`, `commands/`, and `templates/` (spec 0030)
- Resolution precedence is: `$SPECCRAFT_PLUGIN_ROOT` (must validate or hard-error), then `$CLAUDE_PLUGIN_ROOT` if set and valid, then self-derivation via `os.Executable()` → `filepath.EvalSymlinks` → ascend to the nearest validating ancestor (handling installed and dogfood layouts), else exit non-zero naming each source tried (spec 0030)
- Command docs resolve `PLUGIN_ROOT="$(speccraft-state plugin-root)"` once before their first plugin-relative access (failing fast on error), replacing every `$CLAUDE_PLUGIN_ROOT/{bin,commands,templates}` dereference; `hooks/` are exempt (they reliably receive the env var) and this repo's `.devcontainer` exports `SPECCRAFT_PLUGIN_ROOT` at the working tree so dogfood never resolves to a stale cache copy on `PATH` (spec 0030)
- No zsh-reserved identifier (`status`, `path`, `pipestatus`, …) is assigned as a shell variable in any `commands/**/*.lib.sh`, enforced by an exact-form grep guard plus an authoritative real-`zsh -uc "source <lib>"` backstop leg with empty stderr (spec 0030)
- The shipped shell surfaces (`hooks/`, `commands/`, `tools/`, `templates/`, `agents/`, `skills/`) target BSD/macOS userland as well as GNU, enforced by a fixture-first portability meta-guard forbidding TEN GNU-only forms — `sed -i` with no backup suffix, the `0,/re/` address, `tac`, `readlink -f`, `grep -P`, `stat -c`, `date -d`, `base64 -w`, and (spec 0050) `realpath -m` and the GNU-coreutils sha256 checksum tool. Matching is prefix-safe so `sed -i` never matches `sed -i.bak` or `sed -i ''`, is comment- and fence-blind with NO suppression marker (a guard silenceable by annotation is evadable by annotation), and `tests/**` plus `tools/**/*_test.go` are excluded as test-side, never installed. The two forms added by spec 0050 additionally exclude ALL `*.go`, and that scoping is itself a pinned fixture rather than an implicit choice: both are dangerous only as SHELL invocations (Go reaches sha256 via `crypto/sha256` and paths via `path/filepath`), the one shape Go could commit — `exec.Command("sha256sum", …)` — is already outside this line-oriented guard by its own stated limit and is covered by the macOS Go runner, and without the exclusion the clause flagged a PRE-EXISTING, correct Go comment. A guard that fires on prose about a defect, in a language that cannot commit it, trains readers to weaken guards (spec 0049, extended by spec 0050)
- The full `tests/hooks/` bats suite runs on `macos-14` (`hooks-macos`) through Homebrew Bash 5 — macOS ships 3.2, so a runtime `BASH_VERSINFO[0] >= 5` assertion keeps a silently-3.2 job from passing for the wrong reason — and `scripts/assert-no-gnu-userland.sh` runs as a workflow step BEFORE bats, because a job greened by installing GNU userland passes while testing nothing; it is deliberately NOT a bats test since on Linux `tac` resolves legitimately and the assertion would invert (spec 0049). **That ordering made the job fail closed for its entire existence, so the suite never once executed** (spec 0050): the behavioural probe rejected any required tool whose `--version` mentioned `GNU`, and macOS `/usr/bin/grep` answers `grep (BSD grep, GNU compatible) 2.6.0-FreeBSD` — BSD grep advertising GNU *compatibility*. The probe must therefore ask whether a tool NAMES ITSELF a GNU implementation (`(GNU ` or a line-leading `GNU `, the latter load-bearing because gawk prints `GNU Awk 5.1.0` with no parenthesis), strip compatibility CLAIMS first, and read only the first line; and the fixture must model BSD tools that ACCEPT `--version`, which `grep`, `awk` and `date` all do. A precondition assertion guarding a suite has the whole suite as its false-positive cost: a job that cannot START yields no signal in either direction, which is worse than the vacuous green it was written to prevent. First green run: 343/343 on BSD userland, Bash 5.3.15/darwin23
- A GNU-only form that a test EXECUTES is ported, never exempted — the guard's `tests/**` exclusion is a scan-root boundary ("did we ship a GNU-ism?"), not a portability exemption ("does our suite run on BSD?") — and the claim about which files execute one is asserted by a mechanised sweep with a pinned mention-only exclusion list rather than stated in prose, so a miscount fails a test instead of shipping (spec 0049)
- A command lib that shells out to `speccraft-state` resolves it `$SPECCRAFT_STATE_BIN` → `PATH` → plugin-local `bin/` (derived from its own `${BASH_SOURCE[0]:-$0}` location) and names the resolved path in its failure diagnostic; because PATH wins over the plugin-local copy, any CI job that builds the binaries must put them on `PATH` via `$GITHUB_PATH` or a stale ambient copy is used and the suite fails for the wrong reason (spec 0049)
- Coverage topology is checked by the non-CI-gating `scripts/verify-linux-pins.sh`, which reverts each portability fix in a detached worktree (never a temp clone, which can inherit an unclean index), fingerprints the caller tree BEFORE any setup, restarts each mutation from the same clean baseline, traps cleanup on every exit path, and requires a Linux bats failure for each — so no fix is pinned only by the macOS runner and gating that job cannot silently un-pin a bug (spec 0049)
- A behavioural tool probe must match the IMPLEMENTATION name, never the bare string `GNU`. BSD tools legitimately advertise GNU compatibility (`grep (BSD grep, GNU compatible) 2.6.0-FreeBSD`), and BSD tools do NOT uniformly reject `--version` — `grep`, `awk` and `date` all accept it on macOS, so a synthetic "BSD userland" fixture built only from rejecting stubs tests the wrong environment. Match `(GNU ` OR a line-leading `GNU ` (gawk prints `GNU Awk 5.1.0` with no parenthesis, so a paren-anchored pattern alone admits the commonest GNU awk), strip compatibility claims explicitly first, and use the FIRST line only — GNU's later lines carry `GNU General Public License`, boilerplate a GPL-licensed BSD tool can print too (spec 0050)
- Shell path canonicalisation uses `cd "$dir" && pwd -P` with parameter-expansion splitting, never `realpath -m` or `readlink -f`. macOS ships `realpath` WITHOUT `-m`, so in `hooks/pre-tool-use.sh` the call failed under `set -euo pipefail` and the hook exited BEFORE delegating to `speccraft-guard` — leaving both the `state.json` single-writer guard AND the entire TDD invariant inert on macOS, reporting `realpath: illegal option -- m` in place of either guard's message. Dropping `-m` is safe by argument, not luck: only the DIRECTORY need exist, and when it does not the target cannot be `<root>/.speccraft/state.json`, whose directory always exists because the root was found by locating it. Split with `${p%/*}`/`${p##*/}` rather than `dirname`/`basename` — this runs on every write-tool call, and relying on BSD's positional-operand tools to accept `--` is the same class of assumption as the defect being fixed (spec 0050)
- A shell helper needing a checksum DELEGATES to `speccraft-state`, rather than shimming `sha256sum`/`shasum`. `sync_design_fingerprint` piped `reconcile` into the GNU-only tool and died on BSD userland, taking `sync_consolidate_design` with it; it now calls `speccraft-state design-fingerprint <design>`, exposing the `designFingerprint` helper Go ALREADY used for `ledger-archive --expect`. Delegation over a `command -v` fallback deliberately: the shell copy was a second implementation of one number, and a fingerprint whose two producers can drift defeats its own purpose. Where a portable checksum genuinely must stay in shell (a test asserting the binary against an INDEPENDENT computation), the probe and the invocation go on ONE line so the meta-guard's `command -v` exemption applies (spec 0050)
